# Monthly history without AI

This is a portable, data-only updater for an ordinary Python 3.11+ scheduler. It never calls a language model, OpenAI API, Sites tool, Copilot or paid inference service. Its calculations consume **zero model tokens**, whether run daily or monthly. Compute, network, storage and hosting still follow the chosen provider's terms and quotas.

This dedicated public repository contains the updater and government price aggregates only. The initial complete-month summary ends on 2026-09-30. The first manual Actions run and public JSON readback must succeed before a client switches to this endpoint. The full AIUI application, user coordinates, account credentials and annual ZIPs are outside this repository's scope.

The workflow calculates complete past months at 07:23 Europe/Paris on day 1. Days 2 and 3 provide automatic retry opportunities after failure. Once a month's result is saved, those repeat runs skip downloads/calculation and create no empty commit. Persistent failures still require attention; source data/permission changes cannot be guaranteed to repair themselves. Check the repository's Actions tab for actual run status.

`python -B -X utf8 update_history.py --period complete` ends at the last day of the previous month. `--period current` remains an optional daily mode that includes yesterday's partial month, but is not the default workflow. A manual workflow dispatch uses `--force` to recalculate even when the current month is already saved; observe the initial cloud calculation and public-file readback before declaring the service enabled. The initial complete-month output is ready. The AIUI seed/cache period must be migrated when its new endpoint is enabled; the parent project's `tools/activate_history_endpoint.cjs` validates the actual live file and uses a separate complete-month cache key.

The updater downloads official annual ZIPs to temporary storage, validates and aggregates using `build_history.py`, checks completeness/dates/values and replaces `data/history.json` atomically. Failures leave the previous file intact. Source URLs, archive hashes, observation counts, station counts and cutoff are retained. `--today YYYY-MM-DD` and repeated `--archive PATH` support reproducible verification. No user coordinates are involved.

Clients read `https://raw.githubusercontent.com/OULisa2026/french-fuel-monthly-data/main/data/history.json` and preserve a validated dated cache on failure. GitHub supplies the workflow's short-lived repository token; no OpenAI credentials or private Site plugin are required for routine runs.

Provider constraints: [GitHub Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions) currently gives standard public-repository runners free usage, while private repositories have plan-dependent allowances. [Scheduled workflows](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule) may be delayed; public-repository schedules can be disabled after 60 days without repository activity. Successful updates commit changed data, but repository permissions, failures and provider notices still need maintenance. No promise of permanent free or uninterrupted hosting is made.

Data: DGCCRF / [prix-carburants.gouv.fr](https://www.prix-carburants.gouv.fr/rubrique/opendata/), [Licence Ouverte 2.0](https://www.data.gouv.fr/pages/legal/licences/etalab-2.0). Attribute source and observation cutoff; do not imply government endorsement. Statistic: equal-weight station monthly means of reported prices, not a sales/time-weighted average; no carry-forward or interpolation.
